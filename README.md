### Карта своего кода

Каждый свой компонент — это «надстройка»: он не меняет плагины Quartz, а
добавляет поведение поверх уже готовой разметки. Поэтому обновление плагина
в худшем случае отключает надстройку, но не ломает страницу.

| Компонент           | Скрипт                                                           | Что делает                                                                                     |
| ------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `MkvsExplorer`      | `mkvs-explorer.inline.ts`                                        | Подсветка текущей страницы и родителей в Проводнике; ссылка на титульную первой строкой дерева |
| `MkvsTocCollapse`   | `mkvs-toc-collapse.inline.ts`                                    | Сворачивание разделов оглавления и подсветка текущего                                          |
| `MkvsSearch`        | `mkvs-search.inline.ts` + `scripts/mkvs-search-*.ts`             | Путь и счётчик в карточке, панель «‹ 3 / 12 ›», переход к нужному совпадению                   |
| `MkvsGlossary`      | `mkvs-glossary.inline.ts`                                        | Подсказки к терминам глоссария                                                                 |
| `MkvsGlossaryBack`  | `mkvs-glossary-back.inline.ts`                                   | Кнопка «Назад к тексту» на статье глоссария                                                    |
| `MkvsSidebarToggle` | `mkvs-sidebar-toggle.inline.ts` + `mkvs-sidebar-state.inline.ts` | Сворачивание левой колонки на ПК                                                               |
| `MkvsMobileBar`     | `mkvs-mobile-bar.inline.ts`                                      | Перенос кнопок по режиму экрана                                                                |
| `MkvsPrevNext`      | —                                                                | Кнопки «Предыдущее/Следующее» (серверный компонент)                                            |
| `MkvsImprint`       | —                                                                | Выходные данные пособия под текстом титульной страницы работы                                  |

Общие модули для скриптов лежат в `quartz/components/scripts/`:
`mkvs-path.ts` (разбор адреса страницы), `mkvs-spa-history.ts` (состояние
записи истории роутера), `mkvs-search-*.ts` (части поиска).

### Инлайн-скрипты: зачем в конце файла пустой экспорт

Каждый файл `*.inline.ts` заканчивается строкой, которая ничего не делает.
Она нужна только компилятору: компонент импортирует такой файл как **текст**
скрипта, и без экспорта по умолчанию `tsc` ругается TS2306.

Загрузчик `inline-script-loader` (`quartz/cli/handlers.js:365`) вырезает эту
конструкцию перед сборкой, поэтому в браузер она не попадает.

**Важно:** загрузчик ищет её простым `String.replace` по всему файлу — то есть
по первому вхождению подстроки. Поэтому:

- упоминать эту конструкцию текстом в комментариях внутри `*.inline.ts`
  нельзя: вырежется комментарий, а сама строка останется и сломает сборку;
- по той же причине в комментариях таких файлов не должно встречаться и
  отдельное английское слово из шести букв, с которого она начинается —
  загрузчик вторым проходом удаляет и его.

В самих файлах поэтому стоит только короткая ссылка сюда.


### Проверки и CI

Из шести workflow, пришедших из upstream, на форке выполняется только
`deploy.yml` — он публикует сайт. Остальные пять (`ci.yaml`,
`build-preview.yaml`, `deploy-preview.yaml`, `deploy-v5.yaml`,
`docker-build-push.yaml`) закрыты условием
`if: github.repository == 'jackyzha0/quartz'` и на форке не запускаются
никогда.

Поэтому проверки вынесены в свой `.github/workflows/mkvs-ci.yaml`.

**Чужие пять workflow намеренно оставлены как есть.** Они всё равно не
выполняются, а удаление дало бы конфликт при каждом обновлении upstream —
цена выше пользы. Решение записано здесь, чтобы не приниматься заново.

### Что не форматируется

`content/` внесён в `.prettierignore`. Разметка работ рассчитана на плагин
`obsidian-flavored-markdown`, и его правила местами расходятся с CommonMark,
по которому судит Prettier: `prettier --write` по контенту склеивает тело
callout'а с заголовком, ломает вложенность списков и переномеровывает
`1) 2) 3)`. Подробности — в самом `.prettierignore`.

Запускать `npm run format` без этого исключения нельзя.

## Связь с upstream

Точка ветвления — коммит `1beea50` (последний merge dependabot из upstream).
Всё, что меняет `git diff 1beea50 HEAD`, — своё.

Обновление:

```
git fetch upstream
git rebase upstream/v5
```

Свои файлы (`Mkvs*.tsx`, `mkvs-*.ts`, `quartz/styles/mkvs/`, `content/`,
`quartz.config.yaml`, `quartz.ts`) конфликтов не дают: upstream их не знает.
Конфликты возможны ровно в двух местах.

### 1. `quartz/components/scripts/spa.inline.ts`

Единственный изменённый исходник upstream. Добавлено восстановление позиции
прокрутки при переходе «назад» и счётчик глубины переходов (по нему кнопка
«Назад к тексту» понимает, есть ли куда возвращаться).

Вся логика вынесена в `quartz/components/scripts/mkvs-spa-history.ts`; в самом
`spa.inline.ts` остались импорт и несколько однострочных вызовов. Роутер
upstream правит часто, поэтому конфликт вероятен — но он читаемый.

При конфликте: сохранить вызовы `saveScroll()`, `pushEntry(url)` и передачу
`scroll` в `navigate()`, всё остальное брать из upstream.

### 2. `package.json` / `package-lock.json`

Обычные конфликты зависимостей, разрешаются как всегда.

### Чего в upstream НЕ трогаем

`quartz/plugins/quartz-plugins.schema.json` остаётся файлом upstream. Своё
расширение схемы лежит в `quartz/plugins/mkvs-plugins.schema.json` и
подключается к схеме upstream через `allOf`; `quartz.config.yaml` в первой
строке ссылается именно на него. Схема нужна только языковому серверу YAML
(подсказки в редакторе) и на сборку не влияет.

## Как добавить лабораторную работу

1. Создать `content/labNN/` по образцу `content/lab02/`:

   ```
   content/lab02/
     index.md            титульная: цель, подготовка, файлы к работе, литература
     01-theory.md        теория
     02-main.md          основная часть
     03-task-1.md        практическое задание 1
     04-task-2.md        практическое задание 2
     05-self-check.md    вопросы для самопроверки
     img/                иллюстрации
     resources/          ZIP-архив с заготовками
   ```

   ЛР1 устроена иначе (теория и практика в одном `01-main.md`) — это
   историческое, для новых работ образец именно ЛР2.

2. Frontmatter — правила ниже, в разделе «Frontmatter».

3. Общие куски текста (например, порядок защиты работы) не копировать, а
   вставлять транклюзией из `content/_shared/defence.md`:

   ```markdown
   ![[_shared/defence#^defence-checklist]]
   ```

   Служебная страница помечена `unlisted: true`: её нет ни в Проводнике, ни в
   поиске, ни в цепочке «Предыдущее/Следующее», но она собирается — иначе
   транклюзия не нашла бы источник. В `ignorePatterns` её вносить **нельзя**:
   отфильтрованный файл не попадает в `allFiles`, и вставка выведет
   «Transclude of …» вместо текста.

   Вставка блочная, поэтому стоит отдельной строкой; ограничения — те же, что
   у определений глоссария (см. «Соглашение о `^def-`»).

4. Порядок страниц в Проводнике и в кнопках «Предыдущее/Следующее» задаётся
   **заголовком** (`title`), а не именем файла: Проводник сортирует узлы по
   отображаемому имени. Поэтому заголовки подстраниц нумеруются — «1. Основная
   часть», «2. Практическое задание №1». Сравнение числовое, так что «10.»
   встанет после «2.», а не между «1.» и «2.». Имена файлов (`01-`, `02-`, …)
   нужны только для порядка в редакторе.

   Порядок в дереве и в кнопках обязан совпадать; за этим следит тест
   `quartz/components/MkvsPrevNext.test.ts` — он достаёт настоящую сортировку
   Проводника из разметки плагина и сверяет с копией в `MkvsPrevNext.tsx`.

5. Собрать архив с заготовками — см. «Архивы с файлами работ».

### Frontmatter

| Поле                                          | Где                                          | Зачем                                                       |
| --------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------- |
| `title`                                       | на каждой странице                           | заголовок, строка Проводника, кнопки «Предыдущее/Следующее» |
| `tags`                                        | на каждой странице работы                    | теговые страницы; без тегов подстраницы в них не попадают   |
| `lab`, `source`, `revision`, `author`, `year` | только на `labNN/index.md`                   | выходные данные пособия, их выводит `MkvsImprint`           |
| `date`                                        | только там, где дата осмысленна для читателя | иначе дату берёт из git плагин `created-modified-date`      |
| `cssclasses`                                  | по необходимости                             | свои классы на `<body>` страницы                            |

Правило про `date` важно: плагин `created-modified-date` настроен с
приоритетом `frontmatter → git → filesystem`. Если ставить `date` на одних
страницах и не ставить на других произвольно, одна и та же строка «дата» на
разных страницах будет означать разное.

## Как добавить термин глоссария

1. Создать `content/glossary/<slug>.md`. Первый абзац — определение, и он
   помечается **уникальным** блочным маркером:

   ```markdown
   **GPIO** (General-Purpose Input/Output) — порты ввода-вывода… ^def-gpio
   ```

2. Добавить статью в `content/glossary/index.md` — указатель терминов
   поддерживается вручную, «сирот» в нём быть не должно.

3. В тексте работы ссылаться экранированной чертой:
   `[[glossary/gpio\|GPIO]]`. Это принятая в проекте форма, других быть не
   должно.

4. При **первом упоминании термина в связном тексте** работы под ссылкой
   вставляется определение транклюзией:

   ```markdown
   ![[glossary/gpio#^def-gpio]]
   ```

   В перечнях целей, списках файлов и шагах заданий остаётся голая ссылка без
   определения.

### Соглашение о `^def-`

- **Инвариант:** число маркеров `^def-` в `content/glossary/` равно числу
  вставок `#^def-` в работах. Маркер без вставки — хвост; вставка без маркера
  выведет на странице «Transclude of …» вместо определения.
- **Маркеры уникальные** (`^def-gpio`, а не `^def`): Quartz переносит абзац в
  страницу вместе с его `id`, одинаковые имена дали бы повторяющиеся `id`.
- **Транклюзия блочная, а не заголовочная.** Заголовок `## Определение`
  превратил бы все короткие статьи из строки-аннотации в листаемое окошко:
  `mkvs-glossary.inline.ts` выбирает вид подсказки по числу блоков на
  странице статьи.
- **Где вставка работает:** на верхнем уровне документа, внутри нумерованного
  пункта и внутри callout. **Не работает** в середине пункта маркированного
  списка (`- **Термин** — ![[…]]`): вставка блочная и рвёт строку.
- Оформление вставки — `quartz/styles/mkvs/_glossary.scss`.

## Архивы с файлами работ

Исходники пособий лежат **рядом с репозиторием** — в папках вида
`МКВС.26 - ЛРN`, у каждой есть подпапка `Resources` с файлами, которые нужны
студенту при выполнении работы.

`tools/pack-resources.ps1` пакует каждую такую папку в
`content/labNN/resources/mkvs-26-lrN-resources.zip` — оттуда Quartz копирует
архив как обычный ассет. Папку работы скрипт опознаёт по наличию `Resources`,
номер берёт из хвоста имени; работы, для которых страниц на сайте ещё нет,
пропускает. PDF в архивы не попадают: документы собраны на странице
`content/docs/index.md` и открываются в браузере.

**Запускать обязательно после любого изменения в `Resources`** — иначе на
сайте останется старый архив. Архивы перезаписываются целиком, так что
достаточно одного прогона:

```powershell
powershell -ExecutionPolicy Bypass -File tools/pack-resources.ps1
```

Скрипт работает только на Windows и автоматически не вызывается ничем. Это
осознанно: работа над сайтом ведётся с Windows, а переписывание скрипта ради
кроссплатформенности ничего бы не дало.

Размер архива в тексте страницы руками не пишется. В markdown стоит обычная
ссылка на архив — `[Скачать файлы работы](labNN/resources/….zip)`, а класс,
служебные атрибуты и размер добавляет на сборке плагин
`quartz/plugins/transformers/mkvs-download.ts`. Если архива нет на диске,
сборка выводит предупреждение `[mkvs]`.

## PDF и размер репозитория

`content/docs/` — около 123 МБ документации в PDF, крупнейший файл 64 МБ. Это
выше порога предупреждения GitHub (50 МБ) при жёстком лимите 100 МБ на файл.

**Принятое решение: Git LFS включён только для новых PDF** (`.gitattributes`),
история не переписывается.

Почему так:

- переписывание истории (`git lfs migrate import`) ужало бы `.git` с ~97 МБ до
  ~1 МБ, но потребовало бы пересоздать все клоны — цена выше пользы, пока
  клонирование не мешает;
- выносить PDF на внешний хостинг нельзя: документы должны открываться прямо
  в браузере вместе с якорями `#page=N` — ради этого раздел документации и
  делался.

Сам сайт в порядке: 123 МБ существенно ниже лимита GitHub Pages в 1 ГБ.

Перед первым коммитом с новым PDF нужен установленный
[Git LFS](https://git-lfs.com/): `git lfs install`.

## Переводы строк

В репозитории всё хранится с LF (`.gitattributes`: `* text=auto eol=lf`).
Редактор, не уважающий `.gitattributes`, даст шум в диффе; лечится одним
`git add --renormalize .`.
